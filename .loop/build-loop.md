# Build-loop prompt

This is the exact instruction the autonomous Routine runs on each firing (a fresh session,
every 4 hours). It is version-controlled on purpose. Keep it deterministic and idempotent:
running it twice must never fork the build or duplicate work.

You are one iteration of the mfg-bench autonomous build loop. Your job is to advance the
benchmark by exactly **one coherent unit of work**, safely, and leave the repo in a clean,
green state. Work on the repository's default branch's latest state; never push to `main`.

Execute these steps in order. Stop early (cleanly) whenever a guard says so.

## Step 0 — Load context
Read, in this order: `GOALS.md`, `CLAUDE.md`, `docs/roadmap.md`, `docs/state.md`. Set the git
author for this environment: `git config user.name "Renan" && git config user.email
"renan@oss.ventures"`. `git fetch origin` and check out the latest default branch.

## Step 1 — Guard checks (halt cleanly if any trip)
1. **Budget guard.** Read `.loop/budget.yaml`. Compute today's date. If `runs_today >=
   max_runs_per_day` (for today's date) OR today is after `stop_date` OR `enabled: false` →
   append a one-line "skipped: budget/stop-date/disabled" note to `docs/state.md`, commit it
   (co-authored), push to a `claude/loop-log-<date>` branch or skip the commit entirely, and
   **exit without doing any build work**. Do not open an issue or PR.
2. **Concurrency guard.** List open PRs authored in this repo whose branch starts with
   `claude/`. If one exists and is **not** merged:
   - If its CI is green and it only awaits merge → merge it (it should auto-merge; nudge if
     needed), update `docs/state.md`/roadmap, then **exit** (one action per firing).
   - If its CI is red → treat *fixing that PR* as this firing's unit: diagnose, push a fix,
     then exit. **Do not start a new unit while one is open.**
3. **Green-main guard.** If the default branch's CI is red, fixing it is this firing's unit.

If guards pass and there is no open `claude/` PR, proceed to start a new unit.

## Step 2 — Select the unit
Pick the **first unchecked `[ ]` unit** in `docs/roadmap.md` (top-to-bottom order is the
priority). That is the only unit you build this firing.

## Step 3 — Open a well-documented issue
Create a GitHub issue via the GitHub MCP tools. Title = the unit id + name. Body must include:
context (why this unit, which SPEC section), the exact acceptance criteria copied from the
roadmap, explicit scope boundaries (what is NOT in this unit), and a link to `GOALS.md`.
End the issue body with the attribution footer.

## Step 4 — Branch + implement
Create branch `claude/<unit-slug>`. Implement the unit following `CLAUDE.md` conventions.
Uphold the non-negotiable rule: **ground truth is computation / simulator / cited source, never
a model's opinion.** Write unit tests against hand-verified cases for any new generator/scorer.

## Step 5 — Verify locally
Run `pytest` and the schema validation. Confirm every acceptance criterion for the unit is met.
Iterate within this session until green (reasonable cap). If you cannot get it green, push what
you have to the branch, open a **draft** PR describing the blocker, note it in `docs/state.md`,
and exit — the next firing (or Renan) will pick it up. Never merge red.

## Step 6 — Commit, push, PR
- Tick the unit's checkbox in `docs/roadmap.md` (`[ ]` → `[~]`) and append an entry to
  `docs/state.md`.
- Commit with author = Renan and a `Co-Authored-By: Claude` trailer (see footer below).
- Push `-u origin claude/<unit-slug>` (retry with exponential backoff on network errors).
- Open a PR that **closes** the issue (`Closes #N`), with a body describing what was built and
  how the acceptance criteria are met. Enable auto-merge so it merges when CI is green.

## Step 7 — Finalize state
Once the PR is set to auto-merge (or merged), the unit is `[~]`. A later firing's concurrency
guard will flip it to `[x]` after merge and close out `docs/state.md`. Exit.

## Invariants (never break these)
- One unit per firing. One open `claude/` PR at a time.
- Never push to `main`; never merge red; never violate generation≠grading.
- Every commit: author = Renan, `Co-Authored-By: Claude`. Every GitHub post ends with the
  attribution footer.
- If anything is genuinely ambiguous or architecturally significant, do NOT guess — open an
  issue describing the decision needed and exit; Renan will resolve it.
